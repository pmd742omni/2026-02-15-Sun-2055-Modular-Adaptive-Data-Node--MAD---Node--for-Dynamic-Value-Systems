## 5.3.2 Empirical Analysis by Subsystem

### 1. Portable Node Generator & Preflight Execution
- **Bundle Synthesis Latency**: The complete generation of a standalone portable node folder (including Python server, SQLite storage engine, beacon broadcaster, and glassmorphic HTML/CSS/JS frontend) executed in \(< 45\text{ ms}\).
- **Maintenance Mode Enforcement**: Transitioning a Data Node to `deactivated` mode immediately caused write operations to be rejected with HTTP 503 while preserving read availability.
- **Preflight Dependency Verification**: Automatic inspection of required runtime libraries (`fastapi`, `uvicorn`, `pydantic`, `cryptography`, `qrcode`, `jinja2`) completed in \(< 12\text{ ms}\).

### 2. Customer Digital Banking & Multi-Currency Ledger Performance
- **Wallet Auto-Provisioning**: Wallets instantiated with unique IDs (`ACC-2026-XXXXXX`) in \(< 2.4\text{ ms}\).
- **Atomic P2P Transfers**: Mutual sender balance decrement and recipient increment executed under exclusive transaction lock in \(< 8.1\text{ ms}\) without race conditions.
- **HMAC Audit Signature Generation**: Average HMAC-SHA256 signature calculation latency was \(< 0.12\text{ ms}\) per transaction.

### 3. Bearer Voucher to Wallet Conversion
- **Voucher Deposit Success**: Valid offline bearer vouchers successfully credited to the liquid wallet with status transition `active` \(\to\) `redeemed`.
- **Double-Spend Prevention**: Re-submission of previously redeemed vouchers was rejected with HTTP 400 (`Voucher is already redeemed`) in 100% of trials.

### 4. Point-of-Sale Wallet Debit & Receipt Vault Archiving
- **Wallet Debit at POS**: POS checkouts selecting `payment_method = 'wallet'` debited customer balance and logged `pos_payment` in `wallet_ledger`.
- **Digital Receipt Vaulting**: Item-enriched receipt records with SHA-256 hashes archived in `customer_receipts` table in \(< 3.5\text{ ms}\) and retrieved via keyword search in \(< 1.8\text{ ms}\).
