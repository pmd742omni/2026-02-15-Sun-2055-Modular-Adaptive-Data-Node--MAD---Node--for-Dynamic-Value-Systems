# 4.5 Programming & Algorithmic Implementation

## 4.5.1 Atomic Wallet Transactions & Balance Mutation
To prevent race conditions during rapid concurrent transfers, top-ups, and point-of-sale debits, all wallet ledger mutations execute inside exclusive SQLite WAL write locks with `BEGIN IMMEDIATE`. The algorithm evaluates balance sufficiency, executes balance modification, and appends a cryptographically signed double-entry ledger record.

### Algorithm 4.5.1: Atomic Peer-to-Peer Wallet Transfer
```
Algorithm: ExecuteWalletTransfer(from_user, to_user, currency, amount, tx_type, notes)
Input: Sender username (from_user), Recipient username (to_user), Currency (USD/ZAR/ZWG), Transfer amount (amount > 0)
Output: Transaction confirmation dictionary or throws ValueError

1:  db ← GetDatabaseConnection()
2:  BEGIN IMMEDIATE TRANSACTION on db
3:  TRY:
4:      sender_wallet ← Query("SELECT * FROM wallets WHERE username = ?", from_user)
5:      recipient_wallet ← Query("SELECT * FROM wallets WHERE username = ?", to_user)
6:      IF sender_wallet[currency] < amount THEN:
7:          ROLLBACK db
8:          THROW ValueError("Insufficient sender wallet balance")
9:      END IF
10:     new_sender_bal ← sender_wallet[currency] - amount
11:     new_recipient_bal ← recipient_wallet[currency] + amount
12:     Update("UPDATE wallets SET balance = ? WHERE username = ?", new_sender_bal, from_user)
13:     Update("UPDATE wallets SET balance = ? WHERE username = ?", new_recipient_bal, to_user)
14:     wtx_id ← GenerateUUID()
15:     t_utc ← CurrentISO8601Timestamp()
16:     sig_debit ← HMAC_SHA256(K_vault, wtx_id + "|debit|" + amount + "|" + new_sender_bal)
17:     sig_credit ← HMAC_SHA256(K_vault, wtx_id + "|credit|" + amount + "|" + new_recipient_bal)
18:     InsertLedger(wtx_id + "-deb", sender_wallet.account_number, tx_type, currency, -amount, new_sender_bal, to_user, notes, sig_debit)
19:     InsertLedger(wtx_id + "-crd", recipient_wallet.account_number, tx_type, currency, +amount, new_recipient_bal, from_user, notes, sig_credit)
20:     COMMIT db
21:     RETURN {status: "success", tx_id: wtx_id, sender_new_balance: new_sender_bal}
22: EXCEPT Exception as e:
23:     ROLLBACK db
24:     THROW e
25: FINALLY:
26:     Close(db)
```

## 4.5.2 Bearer Voucher to Bank Account Conversion Algorithm
The voucher deposit pipeline enables offline paper or digital QR bearer vouchers to be deposited into customer bank accounts as liquid spendable credit.

### Algorithm 4.5.2: DepositVoucherToWallet
```
Algorithm: DepositVoucherToWallet(username, vid)
Input: Customer username, Voucher unique identifier (vid)
Output: Conversion result dictionary

1:  db ← GetDatabaseConnection()
2:  BEGIN IMMEDIATE TRANSACTION on db
3:  TRY:
4:      voucher ← Query("SELECT * FROM vouchers WHERE vid = ?", vid)
5:      IF voucher is NULL OR voucher.status != 'active' THEN:
6:          ROLLBACK db
7:          RETURN {success: False, detail: "Voucher not found or already redeemed"}
8:      END IF
9:      IF voucher.expires_at_utc < CurrentISO8601Timestamp() THEN:
10:         Update("UPDATE vouchers SET status = 'expired' WHERE vid = ?", vid)
11:         COMMIT db
12:         RETURN {success: False, detail: "Voucher has expired"}
13:     END IF
14:     expected_sig ← HMAC_SHA256(K_vault, vid + "|" + voucher.business_id + "|" + voucher.value_amount + "|" + voucher.currency + "|" + voucher.expires_at_utc)
15:     IF NOT ConstantTimeCompare(voucher.signature_hmac, expected_sig) THEN:
16:         Update("UPDATE vouchers SET status = 'voided' WHERE vid = ?", vid)
17:         COMMIT db
18:         RETURN {success: False, detail: "Tampered voucher signature"}
19:     END IF
20:     Update("UPDATE vouchers SET status = 'redeemed', redeemed_at_utc = ? WHERE vid = ?", CurrentISO8601Timestamp(), vid)
21:     wallet ← GetOrCreateWallet(username)
22:     new_bal ← wallet[voucher.currency] + voucher.value_amount
23:     Update("UPDATE wallets SET balance = ? WHERE account_number = ?", new_bal, wallet.account_number)
24:     wtx_id ← GenerateUUID()
25:     sig_ledger ← HMAC_SHA256(K_vault, wtx_id + "|voucher_deposit|" + voucher.value_amount + "|" + new_bal)
26:     InsertLedger(wtx_id, wallet.account_number, 'voucher_deposit', voucher.currency, voucher.value_amount, new_bal, voucher.business_id, vid, sig_ledger)
27:     COMMIT db
28:     RETURN {success: True, vid: vid, amount_credited: voucher.value_amount, new_balance: new_bal}
29: FINALLY:
30:     Close(db)
```

## 4.5.3 Cryptographic Receipt Archiving & Verification Pipeline
When a POS transaction completes, the server generates an itemized JSON payload and writes it directly to the customer's personal receipt vault with a SHA-256 hash stamp. The thermal receipt rendering engine draws the QR code dynamically onto an HTML5 `<canvas>` element containing:
```
MADN-RCPT|INV-20260823-A49C74|biz-green-valley|4.50|USD|2026-08-23T19:08:18Z|H_receipt
```
The QR code can be verified instantly by any peer node without network access.
